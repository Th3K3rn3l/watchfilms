# 🎬 WatchFilms

Совместный просмотр фильмов на расстоянии. Фильм лежит только у одного человека (хоста). Второй открывает ссылку в браузере, ничего не скачивая и не устанавливая. Пауза, воспроизведение и перемотка синхронизируются у обоих.

- Один файл ~7 МБ для **Linux** и **Windows**, без зависимостей
- **⚡ Blazing Fast P2P (WebRTC)**: прямое соединение хоста и друга через пробитие NAT (STUN hole-punching). Никаких промежуточных серверов, скорость ограничена только провайдером.
- Бесплатный сервер соединения через **Yandex Cloud Functions** (в бесплатном лимите Яндекса, видеопоток через облако не идёт).
- Резервные публичные туннели (Cloudflare + встроенный Pinggy SSH) при невозможности P2P.
- Фильм любого размера и длины: видео отдаётся кусками, перемотка мгновенная
- Если у кого-то подгружается видео, пауза ставится у обоих, и рассинхрона нет
- Чат, реакции на экране (клавиши 1–8), субтитры `.srt/.vtt` рядом с фильмом (кодировка Windows-1251 тоже поддерживается)

## ⚡ Прямое P2P соединение (Yandex Cloud)

Для максимальной скорости соединения (без лимитов и задержек сторонних туннелей) используется P2P WebRTC:
1. Разверните сигнальную функцию в Yandex Cloud (займёт 2 минуты, см. [yandex/README.md](file:///home/payload/projects/watchfilms/yandex/README.md)).
2. Запустите программу с параметром `-signal`:
   ```bash
   ./watchfilms -signal https://functions.yandexcloud.net/ВАШ_ID_ФУНКЦИИ
   ```
   *(Или просто нажмите «Пригласить» в окне приложения и укажите адрес функции в настройках P2P).*
3. Отправьте другу сгенерированную ссылку. Видеопоток пойдёт напрямую между вашими компьютерами по UDP через NAT!

## Запуск

**Windows:** двойной клик по `watchfilms.exe`.
**Linux:** `./watchfilms` (можно сразу с фильмом: `./watchfilms ~/Видео/film.mp4`).

1. Откроется браузер. Введите имя.
2. **Открыть фильм**: выберите файл.
3. **Пригласить** → **Копировать**: отправьте ссылку другу.

По умолчанию используется встроенный SSH-туннель (Pinggy, порт 443), работающий сразу «из коробки» без загрузки каких-либо внешних утилит. Если вы переключитесь на Cloudflare, программа при необходимости один раз скачает `cloudflared` (~40 МБ) в папку кэша.

## Горячие клавиши

| Клавиша | Действие |
|---|---|
| Пробел / K | пауза / продолжить (у обоих) |
| ← / → | перемотка на 10 с (у обоих) |
| ↑ / ↓ | громкость (только у себя) |
| F | полный экран (чат остаётся сбоку) |
| M | звук вкл/выкл |
| C | показать/скрыть чат |
| Enter | написать в чат |
| 1–8 | реакции |

## Параметры

```
-port 8787         локальный порт
-signal <url>      URL Yandex Cloud Function для сигнального P2P сервера
-ycf <url>         алиас для -signal
-p2p               использовать WebRTC P2P (по умолчанию true)
-tunnel auto       сервис туннеля: auto (Pinggy -> Cloudflare), pinggy, cloudflare, none
-cf-token <token>  токен Cloudflare Named Tunnel (если настроен свой домен в Cloudflare)
-no-tunnel         без публичной ссылки (только локальная сеть / общий VPN, например Tailscale)
-no-browser        не открывать браузер автоматически
```

## Советы

- **Туннели и обход блокировок:** приложение автоматически проверяет доступность ссылки через Cloudflare (`trycloudflare.com`). Если у вас включен VPN (TUN) или провайдер блокирует порты Cloudflare, приложение автоматически переключится на **Pinggy** (SSH по 443 порту). В окне «Пригласить» всегда можно нажать **«Сменить сервис»**, чтобы переключить сервис вручную (Cloudflare ⇄ Pinggy).
- **Формат:** MP4 (H.264 + AAC) воспроизводится в любом браузере. Звук AC3/DTS браузеры не играют.
- **Скорость:** исходящая скорость интернета хоста должна быть выше битрейта фильма. Его видно, если навести мышь на «буфер N с» в панели управления. 1080p обычно 5–10 Мбит/с.
- **VPN:** туннель подключается по TCP (HTTP/2) и умеет привязываться к физическому сетевому адаптеру, поэтому работает и при включенном VPN.
- Ссылка меняется при каждом запуске программы, а если туннель переподключился, кнопка «Пригласить» покажет новую.
